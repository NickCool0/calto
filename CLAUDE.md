# SnapCal — AI-конвертер текста и скриншотов в события Apple Calendar (macOS)

## Источник вдохновения
Функционально ориентируемся на Smart Calendars AI (https://www.smartcalendars.ai/),
но берём только его возможности ввода текста и скриншотов и превращения их в события
календаря — без остальных функций оригинала.

## Что делает приложение
Нативное menu bar приложение для macOS (открытый исходный код, MIT). Пользователь
вставляет из буфера обмена скриншот или текст (приглашение, переписку, афишу,
расписание), приложение отправляет содержимое в LLM по API-ключу пользователя,
получает структурированные данные о событии(-ях), показывает экран проверки перед
сохранением и записывает события в Apple Calendar. Собственного бэкенда нет —
только связь с выбранным LLM-провайдером и с системным календарём.

## Вне рамок MVP
Голосовой ввод, PDF/Excel/CSV, e-mail, мессенджеры, браузерные расширения, публикуемые
ICS-ленты, контакты, поиск свободных слотов, прямые API Google/Microsoft (не нужны —
эти аккаунты уже подключены в самом Apple Calendar), iOS-версия.

## Технический подход
Целевая система — новейшая доступная macOS (27) с использованием всех актуальных
для неё API и возможностей. Конкретный стек, архитектуру и структуру проекта выбери
сам, исходя из своих лучших практик на момент работы — с одним приоритетом:
**максимально нативные инструменты Apple**, минимум сторонних зависимостей
(идеально — вообще без них, если родные API это позволяют). Если для какой-то задачи
на этой версии macOS уже есть системный фреймворк (например, для глобальных горячих
клавиш, доступа к буферу обмена, доступа к календарю, локального OCR, локальных
языковых моделей Apple) — используй его вместо сторонней библиотеки.

Обязательно: проект должен собираться из командной строки (для CI), без Dock-иконки
(только в menu bar), с песочницей (App Sandbox) и корректными разрешениями на доступ
к календарю — без них macOS молча отклоняет доступ, это частая ошибка.

## Календари
У пользователя в Apple Calendar уже подключены iCloud, Google и Exchange аккаунты —
приложение видит и пишет во все из них через системный доступ к календарю, отдельная
интеграция с Google/Microsoft не нужна. Учитывай, что часть аккаунтов (например,
Exchange) может иметь ограничения — например, только одно напоминание на событие;
такие ограничения нужно аккуратно обработать, а не игнорировать.

## Ввод
- Глобальная горячая клавиша открывает окно ввода.
- Клик по иконке в menu bar — то же самое.
- Вставка из буфера обмена (⌘V): скриншоты/изображения и обычный текст.
  Поддержать и drag-and-drop изображения.
- Текстовое поле для дополнительной инструкции пользователя («только встречи с Аней»,
  «напомни за час»).
- Превью вставленного содержимого перед распознаванием.

## LLM-провайдеры
Выбор провайдера и модели — в настройках, можно завести несколько и переключаться.
Как минимум: Anthropic (Claude), OpenAI, Google Gemini, произвольный OpenAI-совместимый
эндпоинт (для локальных моделей вроде Ollama/LM Studio/osaurus и агрегаторов вроде
OpenRouter). Также рассмотри вариант с локальной моделью Apple прямо на устройстве
(Foundation Models / Apple Intelligence), если она доступна на macOS 27 и умеет
достаточно для этой задачи — это был бы самый «нативный» вариант из всех.
Ключи хранятся только в Keychain. Ответ модели должен быть структурированным
(JSON/tool use/структурированный вывод — что предлагает конкретный провайдер),
а не текстом, который парсится вручную регулярками.

## Логика извлечения событий
Модель должна извлекать из текста/скриншота одно или несколько событий: название,
начало и конец (или отметку «весь день»), часовой пояс (если указан явно), место,
ссылку на онлайн-встречу, заметки, напоминания (только если явно упомянуты, иначе
подставляется значение по умолчанию из настроек), правило повторения (только если
явно указано). Относительные даты («завтра», «в четверг») считаются от текущей даты
и часового пояса пользователя, которые передаются в каждый запрос. Неоднозначности
(например, дата без года, неясный формат дня/месяца) не додумываются молча, а
помечаются, чтобы пользователь увидел их на экране проверки.

## Экран проверки
Ничего не сохраняется в календарь автоматически. Пользователь видит список
распознанных событий, может отредактировать любое поле (включая календарь, куда
оно попадёт, и напоминания), увидеть предупреждения о неоднозначностях, о конфликте
по времени с существующими событиями и о вероятных дубликатах, выбрать, какие
события добавить, и подтвердить. После сохранения — возможность отменить (удалить
только что созданные события).

## Настройки
Провайдер и его ключ/модель, календарь по умолчанию, напоминания по умолчанию,
длительность события по умолчанию (если конец не указан), горячая клавиша, запуск
при входе в систему, включение локального распознавания текста на изображении
(для приватности или для моделей без поддержки изображений).

## История
Локальный список последних операций: что было распознано (без хранения самих
изображений), какие события созданы, с возможностью удалить созданное событие
из истории.

## CI на GitHub Actions
Репозиторий публичный (MIT), поэтому используем бесплатные macOS-раннеры GitHub
Actions. Добавь workflow, который при каждом push и pull request: собирает проект
из командной строки с нуля (без локального кэша), прогоняет тесты, публикует
собранное приложение как артефакт сборки. Подпись — ad-hoc (без Apple Developer
аккаунта), это приложение для личного использования, не для App Store. В README
опиши, что скачанный из Actions артефакт нужно один раз разрешить в Gatekeeper
перед запуском.

## Приватность и open source
Никакой телеметрии. Данные уходят только выбранному LLM-провайдеру (или не уходят
никуда, если выбрана локальная модель). README на русском и английском: что делает
приложение, как собрать и запустить, как получить API-ключ у каждого провайдера,
как подключить локальную модель, раздел о приватности, ссылка на smartcalendars.ai
как источник идеи. Лицензия MIT.

## Качество
Покрой тестами логику извлечения/маппинга данных и работу с датами/часовыми поясами
(она не должна зависеть от сети и UI, чтобы её было легко тестировать). Сделай
mock-провайдер, чтобы можно было разрабатывать и проверять интерфейс без реального
API-ключа. Обрабатывай ошибки по-человечески: нет сети, неверный ключ, модель не
поддерживает изображения, невалидный ответ от модели.

## Порядок работы
Работай поэтапно, начиная с минимального каркаса (menu bar, доступ к календарю, CI)
и постепенно добавляя ввод, распознавание с mock-провайдером, экран проверки,
реальных провайдеров, настройки, историю. После каждого этапа: убедись, что проект
собирается и тесты проходят, дай мне краткий отчёт и дождись подтверждения перед
следующим шагом.
